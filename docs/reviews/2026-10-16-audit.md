## Part A: whole-repo audit

**What this repo does:** WizSAT is a local web app. It turns puzzles and graph
problems into SAT formulas, solves them with four solvers (DPLL, CDCL,
WalkSAT, ProbSAT), checks the answers and benchmarks the solvers against each
other. A Python server (FastAPI) runs every job in its own process and stores
results in SQLite; a React page shows them.

**Load assumed:** one person on their own machine, a few browser tabs, up to
one job per CPU core at once, benchmarks up to the 200,000-run limit, inputs up
to the 2,000,000-clause limit.

Each finding was reproduced against the real code unless it says otherwise.

### Must fix

- [ ] **A1. Any website you visit can stop your runs and read your results**
  - **Difficulty:** hard (security)
  - **Needs decision:** which origins and hosts are allowed. Recommendation:
    accept `localhost`, `127.0.0.1` and `[::1]` on any port (so the Vite dev
    server on 5173 keeps working) plus the host given with `--host`; accept
    requests that carry no `Origin` header (curl, scripts, same-origin page
    loads); reject everything else. Alternative: also require a random token
    per server start, which is safer but breaks plain `curl` use of the API.
  - **Problem:** The server (`create_app` in `sat_web/api.py`) listens on
    127.0.0.1 without a login and trusts every request. Browsers send a POST
    without a body to another site without asking first: a request with
    `Origin: http://evil.example` restarted the job numbering (204), and the
    same works for cancel, skip and rerun, so a page can loop over job ids and
    stop a running benchmark. The WebSocket handler (`events`) answers any
    website and hands it every job and result. Any `Host` header is accepted,
    which allows DNS rebinding: a hostile domain that points at 127.0.0.1 and
    then gets full access, delete included.
  - **Fix:** One small middleware that rejects requests whose `Origin` is not
    allowed, Starlette's `TrustedHostMiddleware` for the same hosts, and the
    same Origin check in `events` before `accept()`. About 15 lines.
  - **Done when:** tests in `tests/test_api.py` show that
    - a POST to `/api/jobs/reset-numbering` with `Origin: http://evil.example`
      gets 403 and changes nothing;
    - the same POST with `Origin: http://localhost:8000`, and with no Origin
      header, still works;
    - a GET with `Host: evil.example` gets 400;
    - a WebSocket connection with a foreign Origin is closed before the hello
      message;
    - the end-to-end tests and `npm run dev` (proxy from port 5173) still work.

- [x] **A2. One big variable number in a DIMACS file can freeze the machine** - Done 2026-11-13.
  - **Difficulty:** hard (sits in the path of every solver run)
  - **Problem:** `cdcl()` and `dpll()` size their per-variable arrays by the
    largest variable number, not by how many variables there are. The clauses
    `10000000 0` and `-5 0` took CDCL 20 s and 2.3 GB, and DPLL 10 s and
    1.5 GB. With variable 1,000,000,000 the process was killed for running out
    of memory. The size guard only counts clauses, and the time limit is not
    checked while those arrays are built.
  - **Fix:** In `run_solver` (`sat_core/solver_registry.py`), when the largest
    variable is above 1,000,000 and far above the number of distinct variables,
    renumber the variables 1..n and map the model back. `walksat()` already
    does this internally ("Work on compact variable numbers"); move that code
    up one level. Renumbering keeps the order of the variables, so every
    heuristic makes the same decisions; normal encodings stay below the
    threshold and keep their readable numbers in the logs.
  - **Done when:**
    - a test solves `[[10_000_000], [-5]]` with every solver in under a second
      and gets a model that uses the original numbers (`{5: False,
      10000000: True}` for the complete solvers);
    - a formula whose variables are far apart gives the same status and, for
      CDCL and DPLL, the same number of decisions and conflicts as the same
      formula numbered 1..n;
    - the conflicts column of `scripts/solver_timings.py` is unchanged.

- [ ] **A3. Old ProbSAT benchmarks can no longer be opened case by case or rerun**
  - **Difficulty:** easy
  - **Problem:** To show one row's answer, "Open in Solve" or "Download CNF",
    `_rebuild_case` in `sat_web/api.py` parses the saved benchmark request
    again; `rerun_job` parses it again too. Benchmarks and jobs saved before
    the ProbSAT rewrite store its old `noise` and `adaptive_noise` options
    (every preset with ProbSAT did), and `expand_params` in
    `sat_core/params.py` rejects unknown options: `ParamError
    {'solvers.0.options.noise': 'unknown parameter'}`. All those buttons fail.
  - **Fix:** Rebuilding a case does not need the solvers: in `_rebuild_case`
    parse the request with its solver list replaced by one default solver and
    its rules removed. For Rerun, drop options the solver no longer has before
    validating (one dict comprehension over the solver's fields).
  - **Done when:** a test stores a benchmark whose request has ProbSAT options
    `{"noise": 0.5, "adaptive_noise": false}` and then
    - `GET /api/jobs/{id}/rows/{index}/case` and `.../cnf` return 200;
    - `POST /api/jobs/{id}/rerun` returns 201 and the new job's request has no
      `noise`;
    - the same for a solve job with those options.

### Should fix

- [ ] **A4. A large DIMACS file's text is sent and kept everywhere**
  - **Difficulty:** medium
  - **Needs decision:** how "Edit" gets the text back once the job detail no
    longer carries it. Recommendation: the frontend loads it from the job's
    `instance.cnf` (already downloadable through
    `/api/jobs/{id}/files/instance.cnf`) when Edit is pressed. Alternative: a
    separate endpoint that returns the stored request in full.
  - **Problem:** The pasted CNF text stays inside the job's saved request, and
    `Job.detail` in `sat_web/manager.py` returns the whole request. A 6 MB file
    made every job-detail response 6.25 MB, and the database 12.5 MB for one
    job. The server keeps every DIMACS job's text in memory from startup; at
    the clause limit that is about 40 MB per job, downloaded again on every
    reconnect.
  - **Fix:** In `Job.detail`, replace `request.params.cnf.text` with its
    length; make Edit fetch the text as decided above.
  - **Done when:** the detail response of a DIMACS job with a 1 MB formula is
    under 20 KB, and pressing Edit on that job puts the full text back in the
    form (an end-to-end or API-level test).

- [ ] **A5. A big DIMACS file is parsed three times per encode**
  - **Difficulty:** easy
  - **Problem:** `validate`, `estimate` and `encode` of `DimacsInput`
    (`problems/dimacs_input.py`) each call `parse_formula`, which parses the
    whole text. For a 21 MB file one parse takes 2.1 s, but encoding takes
    5.9 s; every preview while editing takes 5.2 s.
  - **Fix:** Cache the parse: `functools.lru_cache(maxsize=2)` on a small
    function that takes the text.
  - **Done when:** a test that counts calls to `parse_dimacs` sees one call for
    `build()` and one for the preview (`estimate` + `preview`) of the same
    text, and a changed text is parsed again.

- [ ] **A6. Server memory only grows**
  - **Difficulty:** medium
  - **Problem:** Two caches never forget. `CnfLineIndex` in `sat_web/api.py`
    keeps the line offsets of every CNF ever paged: 77 MB for a 2-million-line
    file, kept even after the job is deleted. `JobManager.rows` in
    `sat_web/manager.py` keeps every opened benchmark's rows on the `Job`: a
    Sudoku row costs about 5.4 KB, so a 10,000-run benchmark keeps about 55 MB
    until it is deleted.
  - **Fix:** Keep only the last 4 files in `CnfLineIndex`. For finished jobs,
    read rows from SQLite on each request instead of keeping `job.rows`
    (running jobs still need the list while rows arrive).
  - **Done when:** tests show that paging a fifth CNF evicts the first from
    the index, and that after the rows of a finished benchmark were served,
    its `Job` holds no row list while a second request still returns every
    row.

- [ ] **A7. No test that a crashed worker ends its job**
  - **Difficulty:** easy
  - **Problem:** When a job's process dies without reporting (for example
    killed for memory, see A2), `JobManager._finalize` marks the job failed.
    No test covers it. If a refactor breaks it, the job stays "running" forever
    and blocks one of the parallel job slots.
  - **Fix:** One test in `tests/test_api.py`: start a long benchmark, kill its
    process through `client.app.state.manager.get(id).process.kill()`, wait.
  - **Done when:** that test passes (the job becomes `failed` with "stopped
    unexpectedly" in its error) and fails when the "failed" branch of
    `_finalize` is removed.

- [ ] **A8. Starting the app twice runs two servers on the same data**
  - **Difficulty:** medium
  - **Needs decision:** what the second start does when WizSAT already answers
    on the port. Recommendation: open the browser at the running one and exit
    with a message. Alternative: start anyway on the next port, but refuse
    when the data folder is the same (needs a lock file).
  - **Problem:** If port 8000 is busy, `free_port` in `sat_web/__main__.py`
    takes the next free one. A second `python -m sat_web` starts another
    server on :8001 with the same database and job folders. On load it marks
    the first server's running jobs as interrupted in its own view, and the
    two job lists drift apart. (Found by reading the code, not run.)
  - **Fix:** Before moving to another port, request `/api/health` on the busy
    one; if WizSAT answers, act as decided above.
  - **Done when:** a test starts a tiny HTTP server that answers
    `/api/health` like WizSAT, calls the launcher's port logic, and sees it
    choose "already running" instead of the next port; a busy port that is not
    WizSAT still moves to the next one.

- [ ] **A9. The same "at most one" clause loop is written nine times**
  - **Difficulty:** medium (clause order must not change)
  - **Problem:** `pairwise_at_most_one` in `problems/encoding.py` builds the
    "no two of these are true" clauses, but no encoder uses it; the n_queens,

    encoding (a future idea in `docs/guide/performance.md`) means editing nine

  - **Fix:** Call the helper everywhere, keeping the order in which clauses

  - **Done when:** for one fixed instance of every problem, the clause list is
    identical (same clauses, same order) before and after: record a hash of
    `instance.clauses` first, as a test. The order matters because it changes
    the solvers' decisions and therefore every benchmark number.

- [ ] **A10. Timeout parsing exists three times**

  - **Problem:** `_timeout` in `sat_web/api.py`, `_parse_timeout` in

  - **Done when:** one function is left, and a test runs `solve_job` directly

## Part B: solvers/ simplification

Read in full: `dpll.py`, `cdcl.py`, `walksat.py`. There is no `probsat.py`;
ProbSAT is a mode of `walksat()`.

Not applicable here: DIMACS parsing lives in `sat_core/dimacs.py` and model
checking in `sat_core/verify.py`, so neither is duplicated in the solvers.
Clause storage differs on purpose (counters for DPLL, watched literals for
CDCL, true-count/true-sum for local search); only the occurrence-list builder
is shared (B3).

**Evidence for the "cannot happen" claims (B6, B7, B9):** an
assertion-instrumented copy of `cdcl.py` ran 24,016 times (3,000 random
formulas x 8 configurations, plus random 3-SAT with 90 variables and a 9x9
Sudoku) and every assertion held. The cleanup schedule (first cleanup after
2,000 conflicts) was exercised by the fixed-limit configuration, not by the
large instances.

**Done when, for every item in this part** (they are refactors that must keep
behaviour and speed):

- `python -m unittest tests.test_solver_agreement tests.test_cdcl
  tests.test_walksat tests.test_runtime` passes;
- the conflicts column of `python scripts/solver_timings.py` is the same as
  before the change, and the times are within run-to-run noise;
- the item's own "done when" line, where it has one.

### Shared between solvers

- [ ] **B1. Formula normalisation is copied three times**
  - **Difficulty:** medium (touches all three solvers)
  - **Problem:** `_normalise_formula` exists in `dpll.py`, `cdcl.py` and
    `walksat.py`: three copies of "drop zeros, repeated literals and
    tautologies, collect every variable"; only CDCL's also returns `max_var`.
  - **Fix:** One `normalise_formula(clauses) -> (clauses, sorted_vars,
    has_empty)` in a new `solvers/formula.py`; CDCL takes the last element of
    `sorted_vars` as `max_var`. About 50 lines less.
  - **Done when:** one definition is left and the shared checks above pass.

- [ ] **B2. Option and log setup is copied three times**
  - **Difficulty:** medium
  - **Blocked by:** B1 (it creates the shared module)
  - **Problem:** The same 30 to 40 lines open every solver: `positive_int`,
    the log-mode check, the seeded `random.Random`, boolean option parsing
    (`flag` in CDCL, `bool_option` in WalkSAT), `log_debug`, and the tail of
    `finish`.
  - **Fix:** `positive_int`, `flag`, `make_rng(seed)` and
    `log_settings(options, default_interval) -> (mode, interval,
    verbose_limit)` in the shared module, plus a tiny `DebugLog(prefix, limit,
    callback)` whose call does the existing limit check. Keep each `finish`
    (each fills different stats) but end it with one shared
    `_result(solution, stats, return_stats)`.
  - **Done when:** the shared checks pass and seeded runs give the same model
    and stats as before. Note: the two boolean parsers differ by one alias
    (`walksat` also accepts the string `"enabled"`); merging makes CDCL accept
    it too. Leave the per-flip debug guards in WalkSAT as they are (see "Kept
    on purpose").

- [ ] **B3. Occurrence lists are built the same way twice**
  - **Difficulty:** easy
  - **Blocked by:** B1
  - **Problem:** `dpll()` and `LocalSearchState.__init__` both build
    `occurs[offset + lit]` lists with the same loop.
  - **Fix:** `occurrence_lists(formula, max_var)` in the shared module. It
    runs once per solve, not in a hot loop.
  - **Done when:** the shared checks pass.

### CDCL (`cdcl.py`)

- [ ] **B5. `stats["solver_options"]` is built but never read**
  - **Difficulty:** easy
  - **Problem:** `cdcl()` builds a summary string (`restart_text`,
    `cleanup_text`, `stats["solver_options"]`). `public_stats()` in
    `sat_core/solver_registry.py` drops it by name, and nothing else reads it.
  - **Fix:** Delete the string and the name in `public_stats`'s drop list.
  - **Done when:** the shared checks pass.

- [ ] **B6. `_dedupe_clause` does no work**
  - **Difficulty:** hard (CDCL conflict analysis)
  - **Problem:** A learned clause cannot contain a repeated literal: `seen[var]`
    admits each variable once and the asserting literal is the only one from
    the current level. Conflict clauses are already deduplicated (normalised
    input, or learned by this same rule). The invariant held in all 24,016
    instrumented runs.
  - **Fix:** Delete the function and its two calls in `analyse_conflict`.
  - **Done when:** the shared checks pass.

- [ ] **B7. Four branches cannot be reached**
  - **Difficulty:** hard (CDCL conflict analysis)
  - **Problem:** Each defends against something the algorithm rules out, right
    where the logic is subtlest:
    - the "scan exhausted" fallback (the `else` of the trail scan in
      `analyse_conflict`);
    - `or reason is None` in the test that ends the analysis loop (the
      decision literal is the earliest on its level, so `path_count` is
      already 0 when the scan reaches it);
    - `if not learnt_lits` in the main loop (the learned clause always holds
      the asserting literal);
    - the branch for a failed `enqueue(learnt_lits[0], ...)` after the
      backjump (the asserting literal is always unassigned there).
  - **Fix:** Remove all four; if a guard is wanted, one `assert` after the
    scan loop.
  - **Done when:** the shared checks pass. All four held under assertion in
    every instrumented run; after removal a future bug would crash instead of
    continuing silently.

- [ ] **B8. The assignment state is stored twice**
  - **Difficulty:** hard (CDCL hot path)
  - **Problem:** `assignment[var]` (None/True/False) always equals
    `val[offset + var]` (UNASSIGNED/TRUE/FALSE); both are written in `enqueue`
    and `backtrack`.
  - **Fix:** Drop `assignment`; read `val[offset + var]` in `enqueue`,
    `pick_heap_var`, `pick_random_var` and where the final model is built
    (map TRUE to True there).
  - **Done when:** the shared checks pass; expect speed neutral to slightly
    better (one list write less per assignment and per undo).

- [ ] **B9. Three counters for two numbers**
  - **Difficulty:** medium
  - **Problem:** `learned_count` always equals `len(learned_db)`, and
    `learned_sequence` always equals `stats["learned_clauses"]` (both asserted
    on every conflict in the instrumented runs). They are kept in step by hand
    in `add_clause` and `reduce_learned`.
  - **Fix:** Use `len(learned_db)`; set a clause's `created` from
    `stats["learned_clauses"] + 1` when it is made.
  - **Done when:** the shared checks pass and `active_learned_clauses` and
    `avg_lbd` in the stats are unchanged on seeded runs.

- [ ] **B10. `reduce_learned(keep_target, protect_glue)` overwrites its own argument**
  - **Difficulty:** easy
  - **Problem:** In glue mode the passed `keep_target` is ignored and replaced,
    so the `0` at the call site means nothing.
  - **Fix:** One argument: `reduce_learned(keep=None)`, where `None` means
    "protect glue and binary clauses, halve the rest" and a number is a fixed
    limit.
  - **Done when:** the shared checks pass, including the fixed-limit
    configuration of the agreement test.

- [ ] **B11. The phase setup does work it does not need**
  - **Difficulty:** medium (seeded runs must not change)
  - **Problem:** `polarity_score` is computed for every literal in every phase
    mode, and the default branch rewrites `True` into `preferred_phase`, which
    already holds `True`.
  - **Fix:** Run the per-variable loop only when the phase mode is not
    "Positive first"; compute `polarity_score` only for "Polarity based".
  - **Done when:** the shared checks pass and a run with `initial_phase`
    "Random" and a fixed seed gives the same decisions and conflicts as before
    (the rng bits must be drawn in the same variable order).

- [ ] **B12. `cdcl()` is one 810-line function**
  - **Difficulty:** hard
  - **Blocked by:** B5, B6, B7, B8, B9 (smaller function first)
  - **Problem:** Options, heap, propagation, analysis, cleanup and the main
    loop all live in one body, which makes it hard to read.
  - **Fix:** The closures are the speed trick, so keep the hot ones
    (`propagate`, `enqueue`, `analyse_conflict`, the heap) as they are. Move
    only the cold parts out: option parsing to `_read_options()` returning a
    small dataclass, and the conflict branch of the main loop to a nested
    `on_conflict(conflict)`, called once per conflict. Do not move the heap or
    propagation into a class: attribute lookups in the hot path would slow it
    down.
  - **Done when:** the shared checks pass with times within noise.

- [ ] **B13. `restart_count` is a confusing name**
  - **Difficulty:** easy
  - **Problem:** It sits next to `stats["restarts"]` but counts something else:
    restart points, including those that happen at level 0. It is the index
    into the Luby sequence.
  - **Fix:** Rename it to `luby_index`.
  - **Done when:** the shared checks pass.

- **B14. `cdcl_debug` is dead:** covered by A11.

### WalkSAT / ProbSAT (`walksat.py`)

- [ ] **B15. End-of-run bookkeeping is written three times**
  - **Difficulty:** medium
  - **Problem:** The three exits of `walksat()` (model found, cancelled,

  - **Done when:** the shared checks pass and the three stats above are equal

- [ ] **B16. Unused aliases**
  - **Difficulty:** easy
  - **Problem:** `normalise_selection_mode` accepts `"prob_sat"` and
    `"probabilistic"`, and `bool_option` accepts `"enabled"`; nothing in the

  - **Fix:** Accept only `"probsat"` (anything else is WalkSAT), and use the
    shared `flag` from B2 if it exists by then.
  - **Done when:** the shared checks pass.

- [ ] **B17. A guard that is never needed**
  - **Difficulty:** easy
  - **Problem:** `state = None` before the early exits and the `if state else

  - **Fix:** Remove both. A closure looks names up when it runs, so assigning
