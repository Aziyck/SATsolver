## Part A: whole-repo audit

**What this repo does:** WizSAT is a local web app. It turns puzzles and graph
problems into SAT formulas, solves them with four solvers (DPLL, CDCL,
WalkSAT, ProbSAT), checks the answers and benchmarks the solvers against each
other. A Python server (FastAPI) runs every job in its own process and stores
results in SQLite; a React page shows them.

**Load assumed:** one person on their own machine, a few browser tabs, up to
one job per CPU core at once, benchmarks up to the 200,000-run limit, inputs up
to the 2,000,000-clause limit.

Each finding was reproduced against the real code unless it says otherwise.

### Must fix

- [ ] **A1. Any website you visit can stop your runs and read your results**
  (`sat_web/api.py:L273-312`, `L407-423`)
  - **What this is:** The server listens on 127.0.0.1 and has no login, so it
    trusts every request that reaches it.
  - **Problem:** Browsers send a POST without a body to another site without
    asking first. A request with `Origin: http://evil.example` restarted the
    job numbering (204); the same works for cancel, skip and rerun, so a page
    can loop over job ids and stop a running benchmark. The WebSocket (the
    live update channel) also answers any website and hands it every job and
    result. Any `Host` header is accepted, which allows DNS rebinding: a hostile
    domain that points at 127.0.0.1 and then gets full access, delete
    included.
  - **Fix:** One small middleware that rejects requests whose `Origin` is not
    localhost / 127.0.0.1, plus Starlette's `TrustedHostMiddleware` for the
    same hosts, plus the same Origin check in the WebSocket handler before
    `accept()`. About 15 lines. Keep it working with the Vite dev proxy
    (port 5173) and with `--host` when the user asks for another interface.
  - **If we skip it:** One bad page or ad, open while WizSAT runs, can stop or
    wipe hours of experiments.

- [ ] **A2. One big variable number in a DIMACS file can freeze the machine**
  (`solvers/cdcl.py:L362-363`, `solvers/dpll.py:L154-159`,
  `sat_core/solver_registry.py:L498`)
  - **What this is:** CDCL and DPLL size their arrays by the largest variable
    number, not by how many variables there are.
  - **Problem:** The clauses `10000000 0` and `-5 0` took CDCL 20 s and 2.3 GB,
    and DPLL 10 s and 1.5 GB. With variable 1,000,000,000 the process was
    killed for running out of memory. The size guard only counts clauses, and
    the time limit is not checked while those arrays are built.
  - **Fix:** In `run_solver`, when the largest variable is above 1,000,000 and
    far above the number of distinct variables, renumber them 1..n and map the
    model back. WalkSAT already does this (`solvers/walksat.py:L410-415`);
    move that code up one level. Renumbering keeps the variable order, so
    every heuristic makes the same decisions; normal encodings stay below the
    threshold and keep their readable numbers in the logs.
  - **If we skip it:** One odd file (a typo, or a generator that numbers
    variables by hash) can lock up the machine.

- [ ] **A3. Old ProbSAT benchmarks can no longer be opened case by case or
  rerun** (`sat_web/api.py:L365`, `L288`; `sat_core/params.py:L441-443`)
  - **What this is:** To show one row's answer, "Open in Solve" or
    "Download CNF", the server parses the saved benchmark request again.
    Rerun parses it again too.
  - **Problem:** Benchmarks and jobs saved before the ProbSAT rewrite store
    its old `noise` option (every preset with ProbSAT did). The parser rejects
    unknown options: `ParamError {'solvers.0.options.noise': 'unknown
    parameter'}`, so all those buttons fail.
  - **Fix:** Rebuilding a case does not need the solvers: in `_rebuild_case`
    parse `{**job.request, "solvers": [{"solver": "cdcl"}], "rules": []}`.
    For Rerun, drop options the solver no longer has before validating (one
    dict comprehension over `spec.fields`).
  - **If we skip it:** Results from before the rewrite cannot be inspected or
    repeated, including thesis runs.

### Should fix

- [ ] **A4. A large DIMACS file's text is sent and kept everywhere**
  (`sat_web/manager.py:L117-129`, `sat_web/api.py:L93`)
  - **What this is:** The pasted CNF text stays inside the job's saved request.
  - **Problem:** A 6 MB file made every job-detail response 6.25 MB, and the
    database 12.5 MB for one job. The server keeps every DIMACS job's text in
    memory from startup; at the clause limit that is about 40 MB per job,
    downloaded again on every reconnect.
  - **Fix:** In `Job.detail`, replace `request.params.cnf.text` with its size.
    "Edit" loads the text from the job's `instance.cnf`, which is already
    written.
  - **If we skip it:** Slow job pages and server memory that grows with every
    big file solved.

- [ ] **A5. A big DIMACS file is parsed three times per encode**
  (`problems/dimacs_input.py:L51-73`)
  - **What this is:** `validate`, `estimate` and `encode` each parse the whole
    text again.
  - **Problem:** For a 21 MB file one parse takes 2.1 s, but encoding takes
    5.9 s. Every preview while editing takes 5.2 s.
  - **Fix:** Cache the parse: `functools.lru_cache(maxsize=2)` on a small
    function that takes the text.
  - **If we skip it:** Benchmarks over big files spend three times as long just
    reading them.

- [ ] **A6. Server memory only grows** (`sat_web/api.py:L121-151`,
  `sat_web/manager.py:L257-262`)
  - **What this is:** Two caches that never forget: the CNF line index used
    for paging, and every benchmark's rows.
  - **Problem:** Paging through a 2-million-line CNF keeps 77 MB of line
    offsets until the server stops, even after the job is deleted. A Sudoku
    row costs about 5.4 KB, so opening a 10,000-run benchmark keeps about
    55 MB until it is deleted.
  - **Fix:** Keep only the last 4 files in `CnfLineIndex`. For finished jobs,
    read rows from SQLite on each request instead of keeping `job.rows`.
  - **If we skip it:** A long session slowly climbs into gigabytes.

- [ ] **A7. No test that a crashed worker ends its job**
  (`sat_web/manager.py:L428-433`)
  - **What this is:** When a job's process dies without reporting (for example
    killed for memory, see A2), `_finalize` marks the job failed.
  - **Problem:** No test covers it. If a refactor breaks it, the job stays
    "running" forever and blocks one of the parallel job slots.
  - **Fix:** One test in `tests/test_api.py`: start a long benchmark, call
    `client.app.state.manager.get(id).process.kill()`, check the job becomes
    `failed` with "stopped unexpectedly".
  - **If we skip it:** That bug could ship silently.

- [ ] **A8. Starting the app twice runs two servers on the same data**
  (`sat_web/__main__.py:L77-91`, `L117`)
  - **What this is:** If port 8000 is busy, the launcher takes the next free
    port.
  - **Problem:** A second `python -m sat_web` starts another server on :8001
    with the same database and job folders. On load it marks the first
    server's running jobs as interrupted in its own view, and the two job
    lists drift apart. (Found by reading the code, not run.)
  - **Fix:** Before moving to another port, request `/api/health` on the busy
    one. If WizSAT answers, open the browser there and exit.
  - **If we skip it:** Duplicate apps and jobs wrongly shown as interrupted.

- [ ] **A9. The same "at most one" clause loop is written nine times**
  (`problems/encoding.py:L44-51`; the n_queens, graph_coloring, clique,
  independent_set, hamiltonian_path and sudoku encoders)
  - **What this is:** `pairwise_at_most_one` builds the "no two of these are
    true" clauses, but no encoder uses it; each one writes the double loop by
    hand.
  - **Problem:** Switching to a smaller encoding (listed as a future idea in
    `docs/guide/performance.md`) means editing nine places that must stay
    identical.
  - **Fix:** Call the helper everywhere. The `estimate()` tests in
    `tests/test_problems.py` check that clause counts stay exact.
  - **If we skip it:** Encoder changes stay slow and easy to get wrong.

- [ ] **A10. Timeout parsing exists three times** (`sat_web/api.py:L73-82`,
  `sat_core/benchmark.py:L249-258`, `sat_core/jobs.py:L120-121`)
  - **What this is:** Three functions turn a "timeout" value into seconds.
  - **Problem:** They already disagree: the copy in `jobs.py` accepts negative
    values that the other two reject.
  - **Fix:** Keep the one in `benchmark.py` as `parse_timeout` and import it in
    the other two files.
  - **If we skip it:** The next rule change gets made in one place and missed
    in the others.

- [ ] **A11. Dead code** (`sat_core/jobs.py:L42` `JOB_KINDS`,
  `sat_core/models.py:L18` `STATUSES`, `sat_core/solver_registry.py:L252`
  `LOCAL_SEARCH_FIELDS`, `sat_core/dimacs.py:L132-133` `parse_dimacs_text`,
  `solvers/cdcl.py:L993-999` `cdcl_debug`)
  - **What this is:** Names that nothing uses (searched in code, tests, docs
    and the frontend; only their own definition mentions them).
  - **Problem:** Each must be read and kept working for nothing.
  - **Fix:** Delete them. (`cdcl_debug` is also B14.)
  - **If we skip it:** A little more to read and maintain.

**Verdict:** fix A1 to A3 first; each is small and together they close the
security hole, the machine-freezing input and the broken old results.

**Lean:** about -60 lines possible, no dependencies to remove.

**Not checked:** the frontend was spot-checked only (live updates, forms,
Solve, Jobs and Benchmark pages); solver internals were covered by Part B and
the randomized tests; `legacy/`, the docs and the standalone visualisations
were not read; Windows was not run (CI covers its tests).

## Part B: solvers/ simplification

Read in full: `dpll.py` (334 lines), `cdcl.py` (999), `walksat.py` (559).
There is no `probsat.py`; ProbSAT is a mode of `walksat()`.

Not applicable here: DIMACS parsing lives in `sat_core/dimacs.py` and model
checking in `sat_core/verify.py`, so neither is duplicated in the solvers.
Clause storage differs on purpose (counters for DPLL, watched literals for
CDCL, true-count/true-sum for local search); only the occurrence-list builder
is shared (B3).

**Evidence for the "cannot happen" claims (B6, B7, B9):** an
assertion-instrumented copy of `cdcl.py` ran 24,016 times (3,000 random
formulas x 8 configurations, plus random 3-SAT with 90 variables and a 9x9
Sudoku) and every assertion held. The cleanup schedule (first cleanup after
2,000 conflicts) was exercised by the fixed-limit configuration, not by the
large instances.

Goal: behaviour and speed stay identical unless a finding says otherwise.

### Shared between solvers

- [ ] **B1. Formula normalisation is copied three times**
  (`dpll.py:L36-62`, `cdcl.py:L64-102`, `walksat.py:L49-85`)
  - **Problem:** Three copies of "drop zeros, repeated literals and
    tautologies, collect every variable"; only CDCL also returns `max_var`.
  - **Simpler:** One `normalise_formula(clauses) -> (clauses, sorted_vars,
    has_empty)` in a new `solvers/formula.py`; CDCL takes
    `max_var = vars[-1] if vars else 0`. About -50 lines.
  - **Risk:** None for correctness (same algorithm, same output order). Speed
    identical: it runs once per solve.

- [ ] **B2. Option and log setup is copied three times**
  - **Where:**
    - `positive_int`: `dpll.py:L102-106`, `cdcl.py:L239-243`,
      `walksat.py:L247-251`.
    - log-mode check: `dpll.py:L97-100`, `cdcl.py:L225-228`,
      `walksat.py:L291-293`.
    - seeded rng: `cdcl.py:L277-278`, `walksat.py:L289-290`.
    - boolean option parsing: `cdcl.py:L252-257` (`flag`) and
      `walksat.py:L267-274` (`bool_option`).
    - `log_debug`: `dpll.py:L120-125`, `cdcl.py:L306-311`,
      `walksat.py:L368-373`.
    - `finish`: `dpll.py:L113-118`, `cdcl.py:L340-346`,
      `walksat.py:L351-366`.
  - **Problem:** The same 30 to 40 lines of setup at the top of every solver.
  - **Simpler:** `positive_int`, `flag`, `make_rng(seed)` and
    `log_settings(options, default_interval) -> (mode, interval,
    verbose_limit)` in the shared module, plus a tiny
    `DebugLog(prefix, limit, callback)` object whose call does the existing
    limit check. Keep each `finish` (each fills different stats) but end it
    with one shared `_result(solution, stats, return_stats)`.
  - **Risk:** The two boolean parsers differ by one alias (`walksat` also
    accepts the string `"enabled"`); merging them makes CDCL accept it too.
    The app always passes real booleans. Speed: `log_debug` runs per
    decision and per conflict in CDCL; a method call costs about the same as
    the current closure. Leave the per-flip guards in WalkSAT as they are
    (see "Kept on purpose").

- [ ] **B3. Occurrence lists are built the same way twice**
  (`dpll.py:L160-165`, `walksat.py:L127-131` in `LocalSearchState.__init__`)
  - **Problem:** The same "offset = max_var, `occurs[offset + lit].append(i)`"
    builder twice.
  - **Simpler:** `occurrence_lists(formula, max_var)` in the shared module.
  - **Risk:** None. It runs once per solve or try setup, not in a hot loop.

### DPLL (`dpll.py`)

- [ ] **B4. Unused hooks: the `assignment` and `choose_var_fn` parameters**
  (`L67-68`, `L77-80`, `L155-156`, `L249-250`, `L268-276`, `L278-284`,
  `L325-326`)
  - **Problem:** No caller, test, script or doc passes either; they pull in two
    helper functions and three special-case loops (about 30 lines).
  - **Simpler:** Remove both parameters and their code. `max_var` becomes
    `variables[-1]`; the solution is just the comprehension at `L324`.
  - **Risk:** None for the app; decisions are identical. AGENTS.md asks to keep
    the `dpll()` signature backward compatible, so update that line in the
    same change. (Needs your decision.)

### CDCL (`cdcl.py`)

- [ ] **B5. `stats["solver_options"]` is built but never read** (`L283-294`)
  - **Problem:** Twelve lines build a summary string. `public_stats()` drops it
    by name (`sat_core/solver_registry.py:L440`), and nothing else reads it.
  - **Simpler:** Delete `L283-294` and the name in the drop list.
  - **Risk:** None.

- [ ] **B6. `_dedupe_clause` does no work** (`L105-115`, `L695`, `L713`)
  - **Problem:** A learned clause cannot contain a repeated literal: `seen[var]`
    admits each variable once and the asserting literal is the only one from
    the current level. Conflict clauses are already deduplicated (normalised
    input, or learned by this same rule).
  - **Simpler:** Delete the function and both calls.
  - **Risk:** The invariant held in all 24,016 runs (asserted before the call).
    Speed: marginally better, one O(k) pass less per conflict.

- [ ] **B7. Four branches cannot be reached**
  - **Where:**
    - the "scan exhausted" fallback (`L690-695`);
    - `or reason is None` in `L703` (the decision literal is the earliest on
      its level, so `path_count` is already 0 when the scan reaches it);
    - `if not learnt_lits` (`L927-928`; the learned clause always holds the
      asserting literal);
    - the failed-enqueue branch (`L939-942`; after the backjump the asserting
      literal is always unassigned).
  - **Problem:** Each defends against something the algorithm rules out, and
    each adds reading load right where the logic is subtlest.
  - **Simpler:** Remove all four; if a guard is wanted, one `assert` after the
    scan loop.
  - **Risk:** All held under assertion in every run. After removal a future bug
    would crash instead of continuing silently, which is arguably better.

- [ ] **B8. The assignment state is stored twice**: `assignment` (`L362`) and
  `val` (`L374`), both written in `enqueue` (`L497-505`) and `backtrack`
  (`L745-747`)
  - **Problem:** `assignment[var]` (None/True/False) always equals
    `val[offset + var]` (UNASSIGNED/TRUE/FALSE).
  - **Simpler:** Drop `assignment`; read `val[offset + var]` at `L497-500`,
    `L815`, `L861` and `L976` (map TRUE to True there).
  - **Risk:** Low; covered by the agreement test. Speed neutral to slightly
    better (one list write less per assignment and per undo, one addition more
    per heap pop). Measure with `scripts/solver_timings.py`.

- [ ] **B9. Three counters for two numbers**: `learned_count` (`L299`, `L533`,
  `L789`) always equals `len(learned_db)`, and `learned_sequence` (`L281`,
  `L526`) always equals `stats["learned_clauses"]`
  - **Problem:** Two extra counters that must be kept in step by hand.
  - **Simpler:** Use `len(learned_db)`; set `created` from
    `stats["learned_clauses"] + 1` when the clause is made.
  - **Risk:** None; both equalities were asserted on every conflict. `len()` on
    a list is O(1).

- [ ] **B10. `reduce_learned(keep_target, protect_glue)` overwrites its own
  argument** (`L764-781`, called at `L947` with `0`)
  - **Problem:** In glue mode the passed `keep_target` is ignored and replaced,
    so the `0` at the call site means nothing.
  - **Simpler:** One argument: `reduce_learned(keep=None)`, where `None` means
    "protect glue and binary clauses, halve the rest" and a number is a fixed
    limit.
  - **Risk:** None.

- [ ] **B11. The phase setup does work it does not need** (`L395-415`)
  - **Problem:** `polarity_score` is computed for every literal in every phase
    mode, and the `else` branch rewrites `True` into an array that already
    holds `True`.
  - **Simpler:** Run the loop only when `initial_phase_mode != "Positive
    first"`; compute `polarity_score` only for "Polarity based".
  - **Risk:** None. "Random" still draws its rng bits in the same variable
    order, so seeded runs stay identical.

- [ ] **B12. `cdcl()` is one 810-line function** (`L179-990`)
  - **Problem:** Options, heap, propagation, analysis, cleanup and the main
    loop all live in one body, which makes it hard to read.
  - **Simpler:** The closures are the speed trick, so keep the hot ones
    (`propagate`, `enqueue`, `analyse_conflict`, the heap) as they are. Move
    only the cold parts out: option parsing (`L225-280`) to `_read_options()`
    returning a small dataclass, and the conflict branch of the main loop
    (`L907-966`) to a nested `on_conflict(conflict)`, called once per conflict.
  - **Risk:** No change in correctness. Do not move the heap or propagation
    into a class: attribute lookups in the hot path would slow it down.

- [ ] **B13. `restart_count` is a confusing name** (`L889`, `L958-960`)
  - **Problem:** It sits next to `stats["restarts"]` but counts something else:
    restart points, including those that happen at level 0. It is really the
    Luby index.
  - **Simpler:** Rename it to `luby_index`.
  - **Risk:** None.

- [ ] **B14. `cdcl_debug` is dead** (`L993-999`)
  - **Problem:** A compatibility wrapper with no callers in code, tests or docs.
  - **Simpler:** Delete it. (Same as part of A11.)
  - **Risk:** None.

### WalkSAT / ProbSAT (`walksat.py`)

- [ ] **B15. End-of-run bookkeeping is written three times** (`L468-473` SAT,
  `L481-485` cancel, `L551-556` budget spent)
  - **Problem:** Each exit builds `restart_stats`, `hard_clause_hits` and
    `best_assignment` by hand.
  - **Simpler:** Two small closures: `end_try(final_unsat)` appends the per-try
    entry, and `export(values_or_none)` fills the hits and `best_assignment`.
    Each exit becomes two calls.
  - **Risk:** None. These run once per try, not per flip.

- [ ] **B16. Unused aliases** (`L276-280`, `L273`)
  - **Problem:** `normalise_selection_mode` accepts `"prob_sat"` and
    `"probabilistic"`, and `bool_option` accepts `"enabled"`; nothing in the
    repo sends them (the registry always passes `"walksat"`/`"probsat"` and
    real booleans).
  - **Simpler:** `selection_mode = "probsat" if str(value).strip().lower() ==
    "probsat" else "walksat"`, and the shared `flag` from B2.
  - **Risk:** Only an outside caller using those aliases would notice.

- [ ] **B17. A guard that is never needed**: `state = None` (`L395`) and
  `if state else '-'` (`L389`)
  - **Problem:** `log_progress` is only called after `state` exists; the early
    `None` and its check make the reader wonder when it could be missing.
  - **Simpler:** Remove both. A closure looks names up when it runs, so
    assigning `state` later in the function is enough.
  - **Risk:** None.

### Kept on purpose (not findings)

- `if log_mode == "debug" and verbose_emitted < verbose_limit` around the
  per-flip debug lines (`walksat.py:L503`, `L531`) repeats the check inside
  `log_debug` on purpose: it avoids formatting a string on every flip.
- Per-flip counters kept in local variables (`walksat.py:L337-349`) and copied
  into `stats` later: keeping them in the dict was measurably slower.
- ProbSAT recomputes the clause weights in its debug line (`walksat.py:L494`,
  `L506`), but only in debug mode.
- The countdown in CDCL's main loop (`cdcl.py:L896-900`) covers MOMS and DLIS
  steps that do not propagate.
- An empty formula gives all-True in CDCL and DPLL but all-False in WalkSAT.
  Unifying them would change output, which this review avoided.

**Total:** about -170 of 1,892 lines (B1-B3 about -90, DPLL hooks about -30,
CDCL dead code and counters about -45, WalkSAT about -10).
